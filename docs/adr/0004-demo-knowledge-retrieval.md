# Demo 知识检索与规范事实呈现

状态：accepted（2026-10-07）。用户已授权完整 RAG / GraphRAG，小量代表性数据，独立 worktree 暂不合并。本文只记录实现取舍；最新进度见 [TASK](../../tasks/ceres2-optimization.md)。

政策和商品采用中文单字与二元字组/ASCII BM25、固定真实本地 BGE 与 RRF；检索库是可重复构建的派生内容，Python 业务数据库仍是商品、Offer、订单、资格与写入权威。通过少量数据验证完整管道，不迁移旧业务数据库、索引或全部菜谱。

菜谱采用真实 Microsoft GraphRAG 3.2.0 BYOG，以确定性结构化 Recipe / Ingredient / SKU 原始关系作为输入，运行社区发现、LLM 报告与三个真实向量索引，并通过官方 Local / Global API 查询。没有采用独立图数据库或让 LLM 重新抽取已有关系。GraphRAG / Torch 在独立环境，业务宿主经本地 JSONL worker 读取证据。

实测 Global 自由摘要会将社区局部缺项误说成全库未知，提示词补强后仍出现自相矛盾。因而保留生成报告并附上社区成员原始描述；查询末次选择当前检索上下文的实体数字引用，宿主映射为规范 ID。Local 呈现聚焦事实；Global 保留已检索社区完整规范视图及必需食材→菜谱关系，避免二次模型选择漏项。未知查询为空，模型自身选择的召回单独保留。代价是问答表达受限，无法把任意自由摘要作为可信业务结论；收益是分类、基准用量和 SKU 事实不由自由生成文字重新定义。保留所有失败采样用于评测，不宣称原模型变准确。

图中采购关联不是食品配料、营养或过敏信息；路径可达不证明跨食材替代。人数缩放、整包件数、门店库存、预算、家庭已有数量与明确确认继续沿现有确定性合同处理。生成数据库、Parquet、Lance、报告和模型权重不 Git 跟踪；记录建库内容、脚本、固定依赖、源数据和未提交源码哈希，验收按同版本分层。

同次请求发言的真实采样未满足旧正文 JSON 合同，且单纯去掉 JSON mode 的对照仍产生非法最终正文。因此 Pi 主循环采用原生函数调用与可审校普通过程文本；`finish_response` 接原最终引用参数，并通过 SDK `finishTurn` 结束循环，Python 验证后发布。DeepSeek 当前官方接口允许 thinking disabled 下的 `tool_choice=required`，但本轮实际 `required` 六个过程轮均无正文；保持结束工具而改为 `auto` 的三例对照既完成了原生结束，又产生 5 个文本候选，1 条审校通过并发布。因此生产 main 采用 `auto`，由明确结束工具和 Python 引用核验约束完成；不承诺每轮有文字。Pi `streamSimple` 通过 `samplingParams` 原样传入该字段。没有修改 GraphRAG 的结构化 JSON provider，也没有把普通最终文字解析成猜测引用。这针对本轮观测，不能推论模型普遍不支持混合 content/tools，也不代表自然性已通过。
