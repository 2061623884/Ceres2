# Ceres2 纵切票据拆分记录（已批准）

2026-10-05 15:42 UTC：干净重建与持续实施已获授权。16 项目标、批准依赖与测试接缝保持不变；所有新工程技术验收重置，旧通过仅为归档参考。保留现有前端，Python 业务与 Pi/LangGraph runtime 从干净目录选择性实现；不迁入旧运行状态。所有测试命令仅 Tester 执行；不推送。

## 排序原则

- 首先交付 P01 与 P02 两条 runtime 的独立只读演示，均用隔离 fixture 和实际 SDK/框架，不依赖完整采购、模拟结算或新售后写流程。
- 后续按真实技术阻塞推进；“排在 runtime 之后”是优先级，不伪造成技术依赖。每票只补阻挡该切片的最小旧接口/fixture，不先建全业务恢复大票。
- 每票是用户可演示的纵切片，包含当票所需数据/迁移、业务/API、UI 与测试；无 schema 变更时明确沿用而不硬加迁移。只在确需共用事务边界时做最小内嵌重构，不另开纯数据库、纯前端或纯平台票。
- 下列“验证重点”是未来验收候选，并非本轮执行结果。测试命令交专职测试 Agent；真实模型、页面与用户本人验收分别记录。

## 已批准票据

### P01：Pi 商品查询首切片

**Blocked by：** 无。

**What it delivers：** 用户在可可输入一个商品/品类目标，真实 Node/TypeScript Pi SDK 调用 Python 查询服务、读取结果后自主决定再查详情，最后在现有对话展示有事实依据的回答。只读商品旅程首先可用，不先恢复全部采购业务。

- 交付最小宿主→Pi→只读工具→事实回复的 stdio 协议和配置契约；保留可信 owner、原 revision、真实 SDK 事件，不把旧完整路由包成工具。
- 使用最小两用户商品/供给 fixture；沿用公开 HTTP/SSE 与现有 UI。补本路径必需的类型/ContextPlan 声明，不扩大为整体 V2 helper 恢复。
- 一开始即实现 5 工具轮/15 秒探索上限、早完成/等待、停止闸门与无额外模型的可靠收口，不能先交无限循环再等后票修安全。
- 验证真实 SDK＋受控模型边界、多步工具证据、非法写工具/伪造引用、预算耗尽；真实 provider 兼容与模型自主性另列实测，不用 mock 证明。

### P02：LangGraph 售后查询首切片

**Blocked by：** 无。

**What it delivers：** 用户从隔离演示订单选择一单进入墨墨，真实 Python LangGraph 查询订单、物流、资格或政策，澄清后继续；刷新/重启仍能回到同一 case 的可靠查询结果。

- 以 owner-scoped 合成订单服务适配器工作，不等真实新结算订单；适配器接口与后续单一订单权威一致，不给线上 owner 回退 demo 数据。
- 持久 case/checkpoint、选单版本及必要消息，沿既有墨墨 UI 展示；最小 schema/seed/兼容 saver 迁移随票交付。
- 原 create 工具不暴露给模型；框架阶段控制不等于业务授权，runtime 有界且查询失败不冒充无订单/无资格。
- 验证实际 LangGraph 执行/恢复、两 owner、选单及 checkpoint 越权、查询无多余确认；固定 provider 契约与真实模型另列。

### P03：长期任务与可响应运行

**Blocked by：** P01。

**What it delivers：** 同一用户回到长期可可入口，一个购买任务跨多次运行；处理时可问事实问题、询问进度或修改条件；停止当前处理与放弃分开，关页后有界继续，返回可见持久结果。

- 以查询旅程即可演示，无须先完成加购。唯一长期入口/活动任务、运行状态/消息序号、结果与原版本持久化，必要增量迁移与旧会话 fixture 随票落地。
- 无关事实问答/进度不切任务；新购物目标才换任务；修改及时回应、有用查询继续但结果受新条件校验。停止/换任务 fence 保留，任务结束不清车。
- 完成灰色单动作行滚动替换、三点→流式短消息、自然简洁与适度 emoji；不设未确认的消息条数硬上限。
- 验证多请求响应、旧结果失效、停止与结果竞争、断开 SSE/重连、重启恢复已落库结果、保护终止不自动续跑及迁移保全。

### P04：明确选购与双入口确认

**Blocked by：** P03。

**What it delivers：** 用户明确选定一个直接商品形成版本化清单，经按钮或“就按这个加购”对唯一当前展示方案确认，得到真实购物车结果；重复/旧确认不能再写。

- 打通 Pi 提案→确定性方案服务→清单 UI→共同确认事务；保留货架及逐行明确加购能力。需要的方案/回执字段迁移、最小商品/车 seed 与测试随票。
- 预算/排除、供给/配送再验、SKU/件数、已购 ledger 及事实回执完整贯穿；关联新目标先建议后选定，含糊 ACK 先澄清。
- 修改方案让旧确认失效；停止先到阻止提交，提交先成功如实展示，不自动删车；同 key 同正文重放、异正文冲突。
- 验证 HTTP/SSE、按钮与文本等效、版本/owner/竞争/失败原子性、无授权不写和实际车数量。

### P05：单菜人数与采购修订

**Blocked by：** P04。

**What it delivers：** 用户选择一道菜、指定或修改人数，看到食材需求、整包数量和余量，选择基础调料/改选后重新确认加购。

- 恢复 V1 单菜与 V2 人数完整旅程；保留默认基准不是用户指定人数、pantry 默认不选、未选不代表家中已有、预算协商不等于加购。
- 需求/包装/清单/余量 UI、最小菜谱与多规格 seed、需要的字段迁移和公共行为测试一票交付。
- 验证人数修改、规格选择不丢失、约束/排除/金额、采购修订、加购前后分离与旧确认失效；不在本票实现多菜或供给全局优化。

### P06：多菜合并与来源展示

**Blocked by：** P05。

**What it delivers：** 用户明确追加另一道菜，按兼容食材合并需求后一次取整，看到清单分组来源及已购数量；修改或删除一个目标不破坏另一个目标。

- 完整保留多菜目标、共同预算、contributions、分组与行级已购 ledger；未经选定的新菜只建议。
- 随票补多菜/共享与不兼容规格 fixture、必要来源迁移、UI 及测试，不沿用缺失旧测试包当完成证据。
- 验证共享用量与包装算术、追加/移除/改人数、已经加购部分的重复防护、预算与排除及再次精确确认。

### P07：供给适配与部分采购

**Blocked by：** P06。

**What it delivers：** 单菜或多菜采购遇到规格缺货、库存不足或整种食材无货时，用户看到合法替代与缺项，明确选择部分采购后再独立确认。

- 延续整项需求的整包总价与余量、兼容同食材多规格，保留用户已选规格；不能静默改变目标、条件或把缺货当工具故障。
- 缺货/不足/多规格/整种无货 seed、必需字段迁移、供给预览/缺项 UI 与测试随票。
- 验证完整方案与供给预览/部分清单的差别、两个独立用户决定、购物车防重复、金额/库存变化重确认。

### P08：品类筛选与真实比较

**Blocked by：** P04。

**What it delivers：** 用户浏览或聊天选购可乐等品类，Pi 自主筛选/补查后展示品牌、容量、包装、件数、总价及可比单位价，用户选定后走同一清单与确认入口。

- 比较 response/type、页面上下文与展示引用贯通，真实属性缺失明确未知；有限候选，不新建独立比较管理页。
- 商品属性/多包装 fixture、所需投影或字段迁移、聊天/卡片 UI 与测试同票交付。
- 验证比较前不产生清单/车、空结果不复用旧 ref、真实候选选定、上下文条件保留及无关建议不能自动纳入。

### P09：聊天显式记忆与共享边界

**Blocked by：** P03、P02。

**What it delivers：** 用户可在聊天中保存、查询、更正、删除四类记忆，新购买任务按需使用当前有效偏好；同用户可可与墨墨的实际聊天入口只读取各自需要的背景。

- 修通语义请求→确定性记忆命令→回执→消息展示；SQL 为权威，不加设置页或外部记忆系统。
- 当前条件/显式来源优先、完整查询与受限召回分开、owner/role/来源校验；四类数据及修改/删除版本 seed/必要迁移随票。
- 验证聊天 CRUD、跨任务使用、过期/删除立即不可用、跨 owner 拒绝和角色过滤；本票直接接通 P02 的真实墨墨入口，以隔离订单查询展示需要的相关记忆。实际角色共享在本票完整交付，不等待模拟结算或售后写入。

### P10：可恢复提取与 Dream

**Blocked by：** P09。

**What it delivers：** 用户得到主回复后自动提取/整理记忆，重启后未完工作可恢复；途中显式更正或删除不会被迟到后台结果覆盖。

- 保留四类来源规则、自动 TTL、10 条/24 小时 Dream 门槛、独立模型和主回复不等待；不启用购物监测或通知。
- 最小持久后台状态/唯一来源/租约和删除 fence 迁移、固定时钟 fixture 与通过聊天查询观察结果的 UI 旅程随票。
- 验证中断恢复、重复来源、模型失败不伪报保存、显式保护/不复活、不变内容不续期及真实模型耗时与后台分离。

### P11：历史提醒与重新采购

**Blocked by：** P07、P09。

**What it delivers：** 开始新任务时可简短提示一次相关未完成清单；用户选定历史方案后按当前条件和供给生成新清单、展示变化，并重新确认加购。

- 提醒先核对购物车，忽略/拒绝即停止，绝不自动恢复；复购沿用来源/目标但不沿用旧金额、库存、ledger 或批准。
- 当前人数/预算/排除/有效记忆、多菜数量及缺货路径完整贯通；历史来源与提醒状态最小迁移、两 owner 新旧供给 fixture、UI 与测试同票交付。
- 验证含糊“上次”先选来源、旧快照不变、当前差异与部分采购、重新确认、防重复及提醒去重。

### P12：持久模拟结算订单

**Blocked by：** 无技术前置；实际排期在两个 runtime 首切片之后。

**What it delivers：** 用户从已有购物车独立模拟结算，刷新/重启可见同一订单；订单与本次购物车扣减、回执原子一致。

- 可直接以现有货架明确加购或隔离购物车 fixture 演示，不依赖新 Pi 采购闭环。独立结算摘要/确认、不可变商品价格数量快照、订单列表/详情与“联系墨墨”控件同票。
- canonical order/receipt schema、最小状态/退货属性 seed、合成旧库迁移保全与 UI 测试随票；旧浏览器订单不默认为权威订单。
- 验证价格/车变化刷新摘要、原子失败、并发新增不被误清、key 重放及 owner 隔离；P13 再贯通实际墨墨入口。

### P13：同用户订单与售后贯通

**Blocked by：** P02、P12。

**What it delivers：** 用户在服务器模拟订单上点击墨墨，真实 LangGraph 查询同一订单权威，刷新/重启继续该 case。角色相关记忆由 P09 独立交付，不阻塞本票及 P14 的订单/退款旅程。

- 将 P02 的订单服务接缝接入单一权威，保留独立角色入口；不双写演示库、不自动跳转/消息搬运或跨 Agent 委派。
- 所需 owner/order/case 映射、迁移、状态 fixture 与选单 UI 贯通；未知旧 owner/time 不擅自导入。
- 验证结算→准确选单→查询/资格/进度→恢复、空订单、跨 owner/thread 边界及查询无需确认；P16 再验证与 P09 的记忆共享并行集成结果。

### P14：具体确认与售后回执

**Blocked by：** P13。

**What it delivers：** 用户申请整单仅退款或单明细整行退货，先看具体提案，再明确确认；提交后故障/刷新/重复确认仍得到唯一实际回执。

- LangGraph 的资格→提案→等待确认→重验→幂等提交→回执完整贯通；保留有效 Mercury 政策与金额，不引入上游阈值或人工例外。
- 原子申请/receipt、proposal/approval 版本、case 责任 fence、状态/时间/可退 fixture、所需增量迁移与摘要/确认 UI 同票交付。
- 验证初次意图不写、错误/旧确认拒绝、规则/金额/期限边界、事务失败/提交后 checkpoint 失败、同事项人工负责时不可写。通过受控 case 责任状态测 fence；真实人工后台与此流程的联合演示由 P16 覆盖。

### P15：精简异步人工工单

**Blocked by：** P02。

**What it delivers：** 用户明确要求人工、政策不确定或服务持续失败时，墨墨创建必要上下文工单；人工在小型后台查看、回复/追问、解决/关闭，用户看到进度。

- 最小可信 operator 保护、case 责任/generation fence、工单/消息状态迁移、两用户与处理者 fixture、人工和用户 UI 同票交付。
- 人工负责时 Agent 同事项写暂停；回复不是用户批准，解决/关闭不恢复旧授权。验证去重、隔离、触发/非触发、回复/追问/进度与责任竞争。
- 与 P14 共用同一个 case 责任契约，主会话指定共享定义唯一维护者；必要接口协调不伪造整张票阻塞。实际 canonical 订单和售后确认联合场景在 P16 验证。
