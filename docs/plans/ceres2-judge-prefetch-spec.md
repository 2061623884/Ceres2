## Problem Statement

现有一次 Kev 的 11 个互斥标签同时承担角色、四种可可能力及返回导航，职责混杂；政策查询通常需要 Pi 先决定调用检索工具，再读取事实。希望入口只解决是否转墨墨，在可可内部按需提前准备政策证据，保持购物、政策和混合需求完整，同时核实额外判断是否真正改善调用与延迟。

## Solution

每条新的可可自由文本先由入口 Kev 判断是否需要转墨墨。明确需要时提供切换入口，由用户确认后续接；否则原请求交给可可。墨墨直接进入既有 LangGraph，返回可可只通过按钮。留在可可的请求，由独立政策判断决定是否预检索，再把完整原请求及来源证据实际送进同一个 Pi。Pi 保留理解、购物、回答和必要补查能力；同请求同范围的可复用检索结果不再实际重查。

## User Stories

1. 作为可可用户，我希望每条新文字只先判断是否转墨墨，以免先被强行归入购物或聊天能力标签。
2. 作为用户，我希望是否切页由我确认，职责判断不能代替我的选择或业务授权。
3. 作为用户，我希望入口判断不确定、超时或失败时仍由可可处理原文，且不会偷偷切角色或执行售后操作。
4. 作为墨墨用户，我希望直接继续售后对话，不承担无用的 Kev 调用。
5. 作为墨墨用户，我希望通过明确按钮回可可，自然语言提到返回不能自动切页或续接复合购物请求。
6. 作为用户，我希望选品、确认、返回等结构化按钮绕过 Kev，同时保留身份、版本与授权检查。
7. 作为正在采购的用户，我希望首次理解能看到相关购买任务、活动问题、待澄清内容和引用，使“就选第二个”仍指向正确问题。
8. 作为政策咨询者，我希望明确需要政策时预先检索现有规则，并看到来源、版本与限制。
9. 作为提出混合需求的用户，我希望“选低糖饮品，顺便问退货条件”两部分都得到处理，不丢约束、不拆成第二个回答 Agent。
10. 作为用户，我希望政策判断 no、不确定或失败时普通 Pi 仍能查询，不能把误判变成能力封锁。
11. 作为用户，我希望无匹配、部分证据和检索异常区别展示；缺少规则不能被说成无限制或符合资格。
12. 作为用户，我希望同一请求原样重查复用已有结果，而新政策子问题、条件变化、证据不足或此前失败仍可补查。
13. 作为用户，我希望补查后仍能合法引用本请求中适用的旧证据，不因最后一次检索覆盖其他有效范围。
14. 作为用户，我希望过期、跨用户、跨请求或伪造引用不能变成事实或写入授权。
15. 作为用户，我希望刷新、重放、切页和恢复不会重新执行已确认的加购、售后提交或已经发布的业务结果。
16. 作为项目负责人，我希望能分别看到判断、检索、主模型轮数、时间及用量，未取得的数据明确未知，不预先承诺降本提速。

## Implementation Decisions

### 已确认产品决定

- 入口 Kev 仅服务每个新的 Coco／可可自由文本请求，回答是否需要转 Momo／墨墨；不再输出四能力或返回类标签。Momo 无任何新增 Kev；结构化动作无 Kev。同一请求重放不重新判断。
- yes 只形成用户可接受或拒绝的切换建议；接受后保留完整原文与有效对象引用。入口 no 留在可可；uncertain、timeout、error 也留可可并继续 Pi，但记录真实失败原因，不能冒充明确 no。具体售后由可可说明职责并提供显式入口，不执行售后写入。
- 墨墨回可可仅保留按钮；移除纯返回及所有复合返回标签、自动文字返回与复合返回续接。返回按钮不自动重放已处理消息或继承购物／售后授权。既有提示展示频率、opening 生命周期与显式导航约束未获修改的部分保留。
- 不要求上游再产出四种可可能力。第一次 Pi 理解保留相关任务、活动问题、待澄清事项和有效引用；不能以 null 或伪造 exploration 标签绕过旧裁剪。后续可以按 Pi 已理解的业务阶段组织工具和上下文，确定性服务仍守护事实与写入。
- 可可内部政策判断只决定是否预取。yes 才先调用现有政策检索；no、uncertain、timeout、error 进入普通 Pi，保留政策工具。判断与检索分开，错误不伪装无匹配。不新增投机并行检索。
- 预取和普通工具使用同一现有静态四条政策检索来源。Pi 收到完整原请求、检索条件、证据内容、来源和状态；不是仅把 raw state 存在宿主而模型看不到。证据是事实材料，不是更高优先级指令；不伪造没有对应模型调用的 tool result。
- 只有一个 Pi；不引入 EvidenceAnswerer。预取不能提前登记购物意图、改掉原文或消耗购买任务授权；混合请求仍保留所有子问题和条件，购物与政策结果各用真实引用。
- 本请求同查询范围复用已有结果，不重复实际检索。新政策子问题、条件变化、证据不足或此前失败允许补查。禁止会话级 rag_done 一刀切移除政策工具；检索成功不等于整条请求已被充分覆盖。
- Python 继续是身份、事实、授权、事务与回执唯一权威；Pi 与 LangGraph 分工及人工责任保护不变。政策是一般规则，不证明特定订单资格，不授权加购、退款或退货。

### 工程落实基线（2026-10-07 随四票实施授权采用）

- 复用既有公开 HTTP/SSE 与 typed UI 动作接缝验收；这些是已批准接缝，本轮建议继续沿用，不新增用户访谈或专用测试 API。
- 建议首次使用稳定的可可角色级基础 Prompt／工具集合，保留当前任务、活动问题及待澄清引用，先让 Pi 理解原文，再由既有 guide_request 及已确认业务阶段控制后续相关性；不增设四能力分类器。需同步迁移首次 Prompt、工具和上下文三个消费者，不能只改类型。代价是首次输入可能更长、工具更多，不承诺 token 或费用下降。
- 建议 yes 后首次预取直接以完整原始文字作为 query，category 不指定，沿用现有检索的关键词行为；不再调用参数抽取 judge，也不凭空推断政策类别。把这些实际参数同证据一起交 Pi，供其按原范围复用或用更明确的新子问题补查。混合需求 fixture 必须核对实际参数及全部原文；这是最小工程提案，不宣称其召回已足够。
- 预取成功时建议在 Python 当前请求证据注册表登记真实 policy_ref，并把同一引用及其证据送入模型上下文，使既有政策结果／混合结果能消费它；不另设绕过引用验证的纯文本通道。
- 按请求保存最小判断与证据记录，区分未尝试、成功、空结果、部分覆盖、错误，并记录节点用途、结果、耗时、原因及规则／来源版本。复用身份至少包含可信 owner、session／request、查询与类别／有效条件范围、知识版本；实际字段依现有契约最小落实，不引入通用缓存管理器、跨进程 SQLite 缓存架构或无需求数据库迁移。
- 以检索实际参数和可信条件判断同范围，不能仅靠模型宣称“相同”或字符串近似相等。安全的参数规范化须不合并业务上不同的问题。空结果可复用其“此范围无匹配”事实，不代表全面覆盖；部分结果可复用已有材料并补足未覆盖范围。失败不是成功缓存，重新尝试仍受已有执行预算约束。
- 执行侧守卫负责实际去重，包括当前调度中可能出现的同批重复／并发调用；命中时返回对应证据，不只拒绝并迫使模型盲转下一轮。模型提示只作辅助，不能单独承担去重、安全或引用合法性。若上下文被裁剪，恢复已有材料而非只有失效指针。
- 引用检查应从“只有最后一次有效”调整为“当前可信请求、权限、版本、范围内实际获得且仍适用”；有效早期引用可继续使用，补查不能自动宣称完整覆盖。不同请求、跨 owner、旧知识版本、伪造或已失效引用不能混入。用户可见来源与未知条件仍由权威事实生成。
- 优先沿用现有 provider 超时和运行预算；不把参考项目的阈值／批量数当成本项目产品决定，不虚构用户批准的阈值。不额外加入隐藏重试或级联 fallback；新增数值、重试或预算变化必须另有明确依据，并在实施前列明。本规格未批准新数值。
- 计时工程提案：端到端测量从新文字被权威入口接纳开始，完整包含入口判断、政策判断、预取、Pi。基线 UI 分离 /routes 与 Pi 准入，前一入口不在后一个 Pi deadline 内；直接 Guide 准入则在 authorize_text 前创建 deadline，可能已包含内部入口判断。须按实际路径分别记录，不能作相反的笼统结论。建议政策判断／预取进入可可处理时启动并共享既有 Pi 运行阶段 deadline，不给每阶段重置预算；入口仍使用既有独立超时并计入总延迟。每次进入检索／Pi 及发布结果前检查取消、当前请求与相关剩余时间。局部失败且运行仍有效才继续；运行截止或已停止按既有终止语义返回，不因 fallback 额外启动 Pi。实施前核实并记录真实时钟边界与该提案适配；任何预算数值变化另列依据，未批准新的端到端时限。
- 判断／证据记录不保存新的业务写入授权；重放使用既有请求身份、版本检查与回执。已完成结果不因新流程再执行；旧 11 类回执只是历史，不触发被移除的自动文字返回。新版本遇到不可兼容的未完成旧导航请求需明确失效并要求重新发起，不能猜测或重放写入。

## Testing Decisions

好测试从真实公开入口驱动，观察 SSE／typed UI、模型实际接收到的上下文、检索调用及权威业务读回；不以私有函数形状代替行为。provider／检索边界使用可控 fixture 覆盖错误与计数；真实调用另建证据，不用 mock 代替实测。

- 01：角色 yes/no/uncertain/timeout/error；Coco 新文字一次入口判断，Momo／按钮零 Kev，重放不增调用；切换确认／拒绝；按钮返回无写入；自然语言及复合返回不导航；已有任务、活动问题、待澄清续接；旧回执与跨 opening／角色／owner／版本冲突。
- 02：纯政策、普通购物、聊天、购物＋政策；政策判断所有分支，命中／空／异常／部分证据；模型真实输入含原文、证据与来源；无订单也能问一般政策；未匹配／未知不会变成资格与提交。
- 03：预取后原样工具调用、同批重复、并发条件适用时；不同类别／子问题／条件、新请求与知识版本；早期有效 ref、多来源混合、伪造／跨用户 ref；部分及失败补查、上下文裁剪后材料可用；refresh／重放／停止恢复不新增写入。
- 04：同一最终候选的公开入口、真实 Pi SDK、typed UI／真实页面及业务读回联测。回归采购数量／约束／预算／确认加购、政策来源、订单／售后确认／人工责任、停止与恢复、历史方案／记忆、结果先行流式展示。缺失能力或凭据如实阻塞对应门槛。

### 实测与性能矩阵

固定旧实现对照与新候选各自完整源码版本，固定政策数据、商品供给、用例、Prompt、模型及配置；同一候选内所有新功能结果不得拼接不同源码窗口。配对比较固定用户当前已批准的实际模型／provider，记录精确名称与配置；不指定或切换主模型来获取性能结论。Kev 使用现有 provider 契约，本轮不做模型选型。

用例至少包含：纯政策命中；政策＋购物混合；无需政策；入口转墨墨及确认；Momo 直接输入／返回按钮；入口及政策判断故障；无匹配／部分／检索异常；同范围复用与新子问题补查。每类记录正确性、完整需求覆盖、引用与授权安全；节点调用数与实际 HTTP 数分开，记录实际检索次数、复用／补查次数、Pi 模型轮数、首字及最终回复耗时、P50/P95（注明样本量）、tokens、provider 用量／可得成本与失败原因。

真实采样前由主会话与 Tester 冻结有限用例清单、每例重复次数、调用顺序及整次实验的时间或费用上限，沿用可用且已授权的额度；没有足够授权或 provider 计费信息时先澄清，不启动无界采样。不在本规格臆造数字或额外费用许可。达到约定上限即停止并保留失败／超时样本；样本不足不能报告稳定 P95 或可靠降本结论。

在实施后的对照方案中同时比较旧路径与新完整路径，并用调用轨迹区分“省实际检索”与“省主模型工具选择轮次”。新增 judge 或上下文可能增加成本；不能以去重次数推导降本。无 provider usage、计价或足够时延样本时写未知／未验证，不能填零或保证改善。质量及安全失败不能用速度抵销。没有另行批准的数值性能达标线；结果供用户决定收益与后续优化。

## Out of Scope

商品预检索判断、向量或新 RAG 框架、多 Agent／第二回答 Agent、全套 Mu／learn-claude-code 移植、模型选型、比较与探索库存筛选统一、跨请求／跨轮缓存平台、通用状态框架、无依据 schema 迁移，以及旧阶段尚未完成的其他产品扩展。前端实现／前端文件修改不在本次云端范围，由用户本地处理；typed UI／浏览器验收要求保留交接，不能用服务端测试替代。2026-10-07 已批准范围内的实施、Tester 验证和分支推送，不再受原文档草案阶段的禁止执行文字限制。
