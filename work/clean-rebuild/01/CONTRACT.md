# TASK01 minimal contracts

- Public routes retain `/api/v1/guide/sessions`, session read, messages read, turns/stream, turns/stop and supply-context revision. Only trusted canonical cookie identity chooses owner. No cart/payment/write tool.
- Each accepted request has an opaque host run id, owner/session scope, immutable task/session revision anchor, request-body digest, 15-second monotonic deadline and persistent receipt reservation. Same request/body replays a completed receipt; changed body conflicts; another owner cannot read or stop it.
- Host spawns one fresh Node worker per run. JSONL uses start, tool_call, tool_result, event, result and error frames. Tool ids correlate results; worker events are actual Pi SDK lifecycle events projected without model prose/thinking. The worker holds no database path or owner-selectable parameters.
- Actual Pi SDK `@earendil-works/pi-agent-core` 1.0.3 owns the model/tool loop. Only search_products and product_details are declared; candidate refs are minted in Python and only usable in their originating run. Five completed tool batches or 15 seconds from host acceptance ends exploration without a final extra model call.
- Model final output chooses completed refs or a finite clarification slot. Python validates refs and renders catalog facts. An empty selection after matches never means no matches; no search cannot establish an empty catalog. Provider/worker failures expose a random correlation id, allowlisted error category and SHA256 fingerprint, never raw provider bodies or stderr.
- Final reply uses SQL compare-and-swap on the original session/task versions, checks stop state and atomically persists both public messages and completed receipt. Receipt reservation is separate from final commit; no shopping facts are changed. SSE transport carries accepted/progress/final events and is not business authority.
- Full long-lived conversation/task routing, restart recovery and multi-process run leasing remain TASK02/TASK03 scope. This slice retains the minimal stop/read/history behavior needed for the query journey.
