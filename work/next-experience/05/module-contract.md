# TASK05 module contract

## Baseline and ownership

Fixed baseline: ec221f939ef711158f0cd9109d88feec0c94089e (controlled01/02/03 releases). The baseline directory contains exact original role prompts and fixture/source hashes. Sole Tester captured four fixed public journey passes plus the social-aside relevance RED in checks/next05-baseline-red. This is controlled API/SSE evidence only; real model, real browser, natural-language review and user acceptance remain unverified.

The unique prompt source is backend/app/prompts/experience.json, with role-aware expression fragments and ordered role sections. Python loads it through experience.py. Mercury concatenates its own sections unchanged; it remains LangGraph with the existing policy, clarification, failure, proposal and confirmation authority. It has no COCO four-capability enum. The Python Pi boundary sends only the COCO modules to its Node worker. runtime/pi/src/prompt-modules.ts selects relevance; worker.ts still owns actual SDK tool definitions and execution.

No new general state, orchestration service or model call is introduced. Existing history/memory bounds and per-run timeout/tool rounds are unchanged. All Python fact/reference, identity, version and write checks remain authoritative. Module/tool presence is never permission to write.

## Four COCO labels and mixed requests

The capability comes from the same existing Kev decision already stored on the turn. Exploration and purchase modification require overlapping shopping, current-question, dish and multi-goal modules. Factual QA keeps factual queries, read-only recipe lookup, policy, comparison and their relevant context. Chat keeps ordinary expression/validation, status, explicit memory/history management and fact/policy access for mixed asides, omitting purchase/dish execution and current product-choice identities.

The full original user text always reaches Pi. Its existing guide_request tool still interprets relationship to the current task. If that result is new_goal/continue/amend, the same agent's next request restores the shopping sections/tools and existing bounded task references. This is not a second Kev call or capability classifier, and does not perform business actions. It prevents the initial relevance hint from removing a mixed shopping request. No keyword parser or independent intent router is added.

The general-text claim validator remains the existing same-provider validation, under the original deadline; it is not a new classifier. It still rejects invented merchant/execution claims.
